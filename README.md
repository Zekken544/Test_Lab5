**М. Билгүүн-Эрдэнэ — B222270046**

## Орчин

Windows, PowerShell, Postman.

```text
node --version
v25.5.0

newman --version
6.2.2
```

Багшийн өгсөн `server.js` нь Node.js-ийн стандарт сан ашигладаг тул серверт нэмэлт сан суулгах шаардлагагүй.

## Ажиллуулах

Серверийг нэг терминалд ажиллуулна:

```powershell
node server.js
```

Өөр терминалд collection-ийг ажиллуулна:

```powershell
newman run lab05-collection.json
```

Collection variable: `baseUrl = http://localhost:3000`.

Бүтэн гаралт болон exit code хадгалах жишээ:

```powershell
newman run lab05-collection.json 2>&1 |
    Tee-Object -FilePath results/newman-pass.txt
$runExit = $LASTEXITCODE
"exit=$runExit" |
    Tee-Object -FilePath results/newman-pass.txt -Append
```

FAIL туршилтад `lab05-collection-fail.json` ашиглана. DOWN туршилтад серверийг Ctrl+C-ээр зогсоогоод үндсэн collection-ийг ажиллуулна.

## Тестийн дизайн

Үндсэн тестлэх функц нь `POST /registrations` буюу хичээлд бүртгүүлэх үйлдэл юм. Функцээ сонгох → оролтын нөхцөлүүдийг ангилах → төлөөлөх утга сонгох → хүлээгдэх үр дүнг тодорхойлох → Postman тест үүсгэх гэсэн таван алхмыг ашиглав.

### Сонголт ба төлөөлөх утга

| Сонголт | Ангилал | Төлөөлөх утга |
|---|---|---|
| Оюутны хүчинтэй байдал | Идэвхтэй / идэвхгүй / байхгүй | `active`, `inactive`, үүсгээгүй studentID |
| Үзсэн хичээлүүд | Урьдач нөхцөлийг хангана / хангахгүй | `["CS201"]`, `[]` |
| Хичээлийн хүчинтэй байдал | Байгаа / байхгүй | PUT-аар үүсгэсэн courseID, үүсгээгүй courseID |
| Урьдач хичээлийн биелэлт | Бүгд / огт үзээгүй / заримыг үзсэн | Шаардлага `["CS201","CS202"]` үед `["CS201","CS202"]`, `[]`, `["CS201"]` |
| Хүсэлтийн талбар | Бүрэн / дутуу | studentID, courseID хоёулаа / courseID байхгүй |

Оюутан байхгүй үед түүний төлөв болон үзсэн хичээлийг тохируулах боломжгүй. Хичээл байхгүй үед урьдач нөхцөлийг нь шалгах боломжгүй тул эдгээрийг тусдаа хүчинтэй хослол гэж тооцоогүй.

### Тестийн тохиолдлууд

| № | Нөхцөл | Хүлээгдэх HTTP статус | Хүлээгдэх result |
|---|---|---:|---|
| 1 | Идэвхтэй оюутан урьдач нөхцөлийг хангана | 201 | `OK` |
| 2 | Оюутан байхгүй, хичээл байгаа | 200 | `ERROR_NO_STUDENT` |
| 3 | Оюутан идэвхгүй, хичээл байгаа | 200 | `ERROR_INACTIVE_STUDENT` |
| 4 | Идэвхтэй оюутан байгаа, хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| 5 | Хичээл CS201, CS202 шаарддаг; оюутан зөвхөн CS201 үзсэн | 200 | `ERROR_PREREQUISITES`, missing: `["CS202"]` |
| 6 | Оюутан болон хичээл хоёулаа байхгүй | 200 | `ERROR_NO_STUDENT` |
| 7 | Оюутан идэвхгүй, хичээл байхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| 8 | Үзсэн хичээлгүй оюутан урьдач нөхцөлгүй хичээлд бүртгүүлнэ | 201 | `OK` |
| 9 | courseID талбар дутуу | 400 | `ERROR_BAD_REQUEST` |

Тохиолдол бүр шаардлагатай бичлэгээ өөрийн PUT setup хүсэлтээр үүсгэнэ. Байхгүй байх ёстой ID-уудыг ямар ч setup хүсэлтээр үүсгэхгүй. Хоёр бичлэг хоёулаа байхгүй 6-р тохиолдолд PUT setup шаардлагагүй.

POST хүсэлт бүрийн HTTP статус болон `result` утгыг тусдаа `pm.test` шалгалтаар шалгасан. Амжилттай бүртгэлд `registrationID` тоо эсэхийг шалгаж, яг нэг утгатай тэнцүүлээгүй. Учир нь ID сервер ажиллаж байх хугацаанд нэмэгддэг.

## Newman үр дүн

Нийт **9 тестийн тохиолдол**, **21 хүсэлт**, **21 assertion** байна. Доорх assertion тоо нь Newman summary-ийн `assertions executed` утга юм.

| Ажиллуулалт | Requests executed | Requests failed | Assertions executed | Assertions failed | Exit code |
|---|---:|---:|---:|---:|---:|
| PASS | 21 | 0 | 21 | 0 | 0 |
| FAIL | 21 | 0 | 21 | 1 | 1 |
| DOWN | 21 | 21 | 21 | 21 | 1 |

### PASS

Үндсэн `lab05-collection.json` дахь бүх шалгалт амжилттай болсон. Давхар алдаатай үед оюутан байгаа эсэх, дараа нь идэвхтэй эсэхийг хичээлийн шалгалтаас өмнө үнэлж байгааг 6, 7-р тест баталсан.

### Зориудын FAIL

Тусдаа `lab05-collection-fail.json` файлд эхний амжилттай бүртгэлийн статусыг 201 биш, зориуд 200 гэж хүлээсэн. Бусад шалгалтыг өөрчлөөгүй.

```text
expected response to have status code 200 but got 201
```

Нэг assertion унаж, `exit=1` гарсан. Үндсэн PASS collection зөв хэвээр үлдсэн.

### Сервер DOWN

Серверийг зогсоогоод үндсэн collection-ийг ажиллуулахад:

```text
connect ECONNREFUSED 127.0.0.1:3000
```

гэсэн холболтын алдаа гарч, `exit=1` буцаасан. HTTP хариу ирээгүй учраас статус болон JSON шалгалтууд мөн унасан.

FAIL үед сервер хариулсан боловч oracle буюу хүлээлт буруу байсан; DOWN үед сервертэй холбогдож чадаагүй нь интерфейсийн алдаа юм. Nonzero exit code-ийг CI-д тестийн алхам амжилтгүй болсныг илэрхийлэхэд ашиглаж болно.

## Дүгнэлт

Энэ лабораториор хичээлд бүртгүүлэх API-г Postman болон Newman ашиглан шалгав.
Тест дизайны таван алхмаас оролтын хослол болон хүлээгдэх үр дүнг сонгох нь хамгийн их бодол шаардсан.
Оюутан байхгүй үед түүний идэвхтэй төлөвийг тохируулах зэрэг боломжгүй хослолуудыг ялгасан.
Тест бүр өөрийн setup-тай байх нь өмнөх тестийн өгөгдлөөс хамаарахгүй ажиллахад хэрэгтэй байв.
HTTP статусыг дангаар нь шалгах хангалтгүй, учир нь энэ API зарим алдаанд 200 буцаадаг.
Давхар алдааны тестээр оюутны шалгалт хичээлийн шалгалтаас өмнө хийгддэгийг баталсан.
Туршсан есөн тохиолдолд серверийн хүлээгдсэн ажиллагаанаас зөрсөн согог илрээгүй.
Зориуд буруу oracle оруулахад нэг assertion унаж, Newman exit code 1 буцаасан.
Серверийг зогсооход үүсэх холболтын алдаа нь буруу хүлээлтийн алдаанаас өөр болохыг харсан.
README-ийн assertion тоонуудыг хадгалсан Newman гаралттай тааруулж тайлагнав.
